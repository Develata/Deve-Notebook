## Implementation Summary

### Core Changes
1. **环境驱动 CORS 策略**：
   - Production 模式：必须显式设置 `ALLOWED_ORIGINS` 环境变量，否则 panic 阻止启动
   - Development 模式：未提供 `ALLOWED_ORIGINS` 时，回退为 `http://localhost:8080,http://127.0.0.1:8080` 并发出 `warn!` 日志

2. **验证逻辑**：
   - 拒绝空列表
   - 拒绝通配符 `*`
   - 拒绝无效 origin（解析失败时 panic）

3. **废弃行为**：
   - 移除 `port..=port+4` 端口扫描逻辑（3001..3005）
   - 移除硬编码 localhost origins

### Environment Variables
- `DEVE_ENV` — 环境类型（默认 `"production"`）
- `ALLOWED_ORIGINS` — 逗号分隔的允许来源列表（生产必填）

### Fail-Closed Behavior

**Production Mode (DEVE_ENV=production or unset)**:
```bash
# Missing ALLOWED_ORIGINS → panic
DEVE_ENV=production cargo run --bin deve_cli -- serve
# Error: Production mode requires ALLOWED_ORIGINS

# Valid configuration
DEVE_ENV=production ALLOWED_ORIGINS=https://app.example.com cargo run --bin deve_cli -- serve
# ✓ Server starts with restricted CORS
```

**Development Mode (DEVE_ENV=development)**:
```bash
# Missing ALLOWED_ORIGINS → fallback with warning
DEVE_ENV=development cargo run --bin deve_cli -- serve
# WARN: Development mode: allowing localhost CORS origins
# ✓ Server starts with localhost:8080,127.0.0.1:8080

# Explicit origins override fallback
DEVE_ENV=development ALLOWED_ORIGINS=http://localhost:3000 cargo run --bin deve_cli -- serve
# ✓ Server starts with http://localhost:3000 only
```
