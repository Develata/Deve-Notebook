# 📘 Deve-Note Features - Master Index

`docs/features/` defines **what the product does**.

Each chapter mirrors `docs/plan/`, but focuses on:

- user-visible behavior
- concrete workflows
- observable results
- Chrome MCP manual validation instances

`docs/plan/` remains the engineering blueprint.  
`docs/acceptance-cases/` remains the automation-oriented validation set.

Each feature chapter should answer three questions:

1. What can the user do?
2. What should the user see?
3. What exact Chrome MCP scenario proves it?
