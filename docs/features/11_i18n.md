# 11_i18n.md - 多语言体验篇

本章描述界面语言、错误文案和语言切换的用户体验。

## 功能目标

- 用户应能在支持语言之间切换界面。
- 错误提示、状态提示和核心控件文案应保持一致与可理解。

## 功能项

### 1. 语言切换

- 用户可以切换当前界面语言。
- 切换后主要界面文案应立即更新。

### 2. 文案覆盖

- 核心工作流中的标题、按钮、状态、错误提示应有一致语言覆盖。
- 不应出现大面积中英混杂或遗漏键。

### 3. 错误语义一致

- 同一类错误在不同位置应保持语义一致。
- 用户看到的是可理解文案，而不是后端内部错误码。

## 非目标

- 当前阶段不要求所有历史归档文档或开发文档都本地化。
- 当前阶段不允许前端直接显示后端裸自然语言错误作为稳定协议。

## Chrome MCP 验收实例

### I18N-FEAT-01: 语言切换与错误文案

前置条件：

- 打开应用并进入主工作流。

步骤：

1. 打开 Settings 或命令入口切换语言。
2. 查看 Header、Sidebar、Source Control、状态栏文案。
3. 再触发一个明确错误或受限状态。

期望结果：

- 主要文案同步切换。
- 错误提示可理解且与当前语言一致。
