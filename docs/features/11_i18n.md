## 功能目标

- 用户应能在支持语言之间切换界面。
- 错误提示、状态提示和核心控件文案应保持一致与可理解。

## 功能项

### 1. 语言切换

- 用户可以切换当前界面语言。
- 切换后主要界面文案应立即更新。

### 2. 文案覆盖

- 核心工作流中的标题、按钮、状态、错误提示应有一致语言覆盖。
- 登录页作为认证入口，其标题、输入标签、按钮和认证错误提示也属于核心文案覆盖范围。
- 顶部 Header、底部状态栏与移动端 footer 对同一连接/同步状态应复用同一 i18n 文案来源。
- ownership-aware 移除 repo 的 destructive confirmation 必须明确说明：本机
  Ledger/Deve runtime 会永久删除且当前无受支持的 Ledger restore，workspace
  文件与 `.git` 保留。该文案必须来自显式 `remove_irreversible_warning` catalog key，
  不得由Web硬编码或拼接；不得翻译成“仅从列表移除”或“删除全部数据”。
- removal preview、confirmation expiry/stale、typed blocker、`NoScope`与首次Create缺projection base
  必须使用backend code/state对应的i18n key；前端不得解析path、manifest或detail生成控制文案。
- 状态栏加载中与加载进度文案应通过统一 i18n facade 输出，窄屏 compact 文案也应随语言切换。
- Dashboard 的运行时间、存储大小、CPU 百分比与内存数值应通过 i18n/formatting facade 输出，避免组件内手写单位格式。
- 不应出现大面积中英混杂或遗漏键。

### 3. 错误语义一致

- 同一类错误在不同位置应保持语义一致。
- 用户看到的是可理解文案，而不是后端内部错误码。
- workspace ingestion unavailable 在 HTTP、editor WS 与其它 WS mutation 中必须映射为同一能力级本地化文案；前端不得展示或解析 backend detail 来判断可写性。
- workspace ingestion health 的 healthy/transitioning/degraded/unknown 状态与“重启服务”恢复指引必须来自统一 i18n facade，不得在组件内硬编码 watcher/backend 术语。
- Remote Projection push 与 Remote Import 的 locator/provider/session/stale/blocker/limit/apply/cleanup
  错误必须按 `REMOTE_PROJECTION_*` / `REMOTE_IMPORT_*` code 映射；同一 code 在 Command Palette、
  sidebar review、diff 与 receipt notice 中语义一致。
- Remote Import UI 不显示或解析 backend raw detail，也不把 provider、watcher、blob、digest 等内部术语
  拼成用户恢复策略。Apply receipt 的 Pending/Written/Degraded outcome 必须使用后端 typed 状态：Pending
  与 Degraded 都明确说明 Ledger 已提交，不能渲染成可重试 Apply。Apply 未 Mounted 继续复用 workspace
  ingestion unavailable 文案。
- Native AI Provider Settings 失败必须映射为固定、本地化提示；环境管理、revision 冲突、非法设置与暂不可用
  的语义不得依赖或展示 server/runtime 诊断文本，未知响应统一显示暂不可用。
- B4 已激活 typed code 映射并删除旧 Source Control notice/detail-prefix 路径；B5 在独立 Remote Import
  view 中复用同一 i18n code，不新增 raw-detail 分类。

## 非目标

- 当前阶段不要求所有历史归档文档或开发文档都本地化。
- 当前阶段不允许前端直接显示后端裸自然语言错误作为稳定协议。

## Chrome MCP 验收实例

### I18N-FEAT-01: 语言切换与错误文案

前置条件：

- 打开应用并进入主工作流。

步骤：

1. 打开 Settings 或命令入口切换语言。
2. 查看 Header、Sidebar、Source Control、Remote Import、状态栏文案。
3. 再触发一个明确错误或受限状态。

期望结果：

- 主要文案同步切换。
- 错误提示可理解且与当前语言一致。
