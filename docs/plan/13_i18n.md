## 1. Internationalization Strategy (国际化策略) {#i18n-facade-contract}

*   **技术选型**：使用轻量级 `crate::i18n::{Locale, t::*}` facade。
    *   **优势**：零代码生成、低依赖、调用面稳定，适合 768 MB VPS 约束下的前端体积控制。
    *   **实现约束**：根组件初始化 `Locale` 上下文，各组件统一通过 `t::xxx::yyy()` 读取文案。
*   **UI 文本管理**：
    *   核心 UI 文本 **MUST** 全部通过 `t::xxx::yyy()` facade 进行管理，严禁新增硬编码字符串。
*   **Format Handling (格式处理)**:
    *   **Date/Time/Number**: 严禁手动拼装 (e.g., `YYYY-MM-DD`)。**MUST** 使用 `Intl` API (JavaScript) 或 Rust 的 `time` crate 进行本地化格式输出。
*   **Backend Error Handling (后端错误处理)**:
    *   后端 API **MUST NOT** 返回自然语言错误信息 (e.g., "密码错误")。
    *   **MUST** 返回标准错误码 (e.g., `AUTH_INVALID_PASSWORD`)。
    *   前端根据 Error Code 查找 `i18n` 映射表进行展示。
    *   本章只定义错误码目录与前端映射规则；传输层/协议层约束应写入网络或薄客户端账本文档。

## 2. Resource Management (语言资源管理) {#i18n-resource-management}

*   **Structure**: 语言资源默认以 Rust 模块函数组织；若后续迁移到外部资源文件，必须保持 `t::xxx::yyy()` 调用面兼容。
*   **Fallback**: Rust `t::*` facade 对已支持 Locale 的 Key 覆盖由编译期保证；不支持的 Locale 标签 **MUST** 在 locale detection/selection 阶段回退到 `en-US`。若后续迁移为外部资源文件并允许运行期缺 Key，则缺失 Key **MUST** 自动回退到 `en-US`。
*   **Detection**: 启动时优先级:
    1.  User Config (`locale` setting).
    2.  Browser Preference (`navigator.language`).
    3.  Default (`en-US`).


## 3. Related Commands (本章相关命令)

*   `Global: Toggle Language`: 按顺序在支持的语言列表 (e.g., en -> zh -> ja -> en) 中循环切换界面语言。

## 4. Related Configuration (本章相关配置)

*   `locale`: 界面语言设置 (e.g., `en-US`, `zh-CN`).

## 6. Error Code Catalog (错误码目录) {#i18n-error-code-catalog}

本节是错误码清单唯一权威。其他章节 **MUST** 引用本节，不得另建平行错误码目录。

后端 API 返回的标准错误码。前端根据 Error Code 查找 i18n 映射表进行展示。
如需补充调试信息，后端 **MAY** 返回 `detail` 字段；但前端展示与分支判断 **MUST** 仅依赖 `code`，不得依赖自然语言 `detail`。
