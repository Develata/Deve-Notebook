## 2. 本轮发现的关键违规（按双射偏离严重度排序）

### 🔴 P0 — 核心安全边界 / 当前 WIP 阻塞

#### P0-1. Native AI Chat 默认能力越界（§10 ⚠️）
**Plan**：Native AI Chat MUST NOT 默认支持 MCP / Skills / 直接 Source Control 写 / 无确认的文件修改
**代码**：当前 Native AI Chat 已显式拒绝 request tools 与 provider tool calls，MCP runtime/host fns 已移除；仍需持续约束 Skills / note write / source-control 写入不进入默认 native chat tool loop。

**缺失**：没有 "native default" gating 层，没有 PLAN 模式拦截器（PLAN MUST NOT 调用任何工具），没有 `/agents` 路由
**双射状态**：⚠️ 历史偏离已部分修正；MCP 已从代码层移除，剩余风险集中在 Skills / Trusted CLI / 写入确认边界
**证据**：gap-core L62-L66

#### P0-2. Agent Bridge 默认拉 CLI 越界（§13 ⚠️ + §12 ⚠️）
**Plan §13**：`ai.agent_bridge.trusted` 未确认时 MUST NOT 起 CLI；任一条件不满足 MUST 自动回退 `ai.mode = native`
**Plan §12**：条件不满足时 MUST 保持 native，不得静默拉 CLI
**代码**：`apps/cli/src/server/agent_bridge.rs:10`
```rust
const DEFAULT_CLI: &str = "opencode";
let path = std::env::var("AGENT_CLI_PATH").unwrap_or_else(|_| DEFAULT_CLI.to_string());
```
没有任何 `trusted` flag 检查，`handle_agent_chat()` 总是尝试 spawn
**双射状态**：⚠️ 严重违规，可被攻击（外部 CLI 任意 spawn）
**证据**：gap-server L34, L38-L39

### 🟠 P1 — 核心主线遗漏

#### P1-1. Filesystem Watcher 后端实际不存在（§04 ❌）
**Plan**：系统核心 MUST 运行文件系统监听服务，实时监控 Vault
**代码**：`crates/core/src/sync/{scan,handler,scan_file,pending_rename}.rs` 只有 scan helpers + event handler 函数，**没有实际的 notify backend / RecommendedWatcher / watch() 调用**
**影响**：整个 §04 "外部编辑摄取链路" 没有实际触发源。当前可能依赖前端主动 scan 或外部触发
**双射状态**：❌ 完全缺失
**证据**：gap-core L25, L40-L43

#### P1-2. server/mod.rs 251 行回归（硬限 +1）
**原因**：fail-closed 安全加固积累（最近 20 次 commit 全是 `fix: fail closed on ...`）
**性质**：纪律违规但功能正向
**证据**：wc + git log

#### P1-3. Repeated FS signal 不幂等（§04 ⚠️）
**Plan**：重复信号触发 MUST 产生相同候选结果状态
**代码**：`sync/pending.rs:57-66` 每次 upsert 写入 `detected_at: chrono::Utc::now().timestamp_millis()`，导致字节不一致
**影响**：影响幂等性测试与去重逻辑

#### P1-4. WS Handshake 返回 plain text "Unauthorized"（§09 ⚠️）
**Plan**：`401/403` 与 `AUTH_*` 错误码 MUST NOT 被重新包装成普通断网状态；MUST 返回结构化 JSON
**代码**：`apps/cli/src/server/ws/mod.rs:45` 返回 `(StatusCode::UNAUTHORIZED, "Unauthorized")` 字符串
**影响**：WebLightPeer 重连循环不能区分网络断开 vs 会话失效
**证据**：gap-server L19, L24, L26

#### P1-5. SyncRequest 缺 known_vector / Snapshot 缺 server_vector（§05 ⚠️）
**Plan**：`SyncRequest MUST 至少携带 { repo_id, known_vector }`；`Snapshot MUST 携带 server vector`
**代码**：`SyncRequest { repo_id, range }`、`Snapshot { repo_id, base_seq, version, delta_ops }`——`known_vector` 和 `server_vector` 字段都不存在
**影响**：增量同步路由必须依赖隐式假设
**证据**：gap-server L13-L14, gap-core L50-L51

#### P1-6. Reconnect 后重发 SyncHello 缺失（§05 ❌）
**Plan**：重连成功后 MUST 重发 SyncHello；切换 repo 时 MUST 以新 repo_id 重建上下文
**代码**：scope 内未发现重连状态机
**证据**：gap-core L55, gap-server L18
