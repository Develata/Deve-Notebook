## 2. 组件中的硬编码字符串扫描

### 2.1 真正的硬编码用户可见字符串（违规）

| 文件:行 | 字面量 | 严重度 | 说明 |
|---|---|---|---|
| `components/settings.rs:66` | `"中文"` | ⚠️ LOW | 语言选择器自指标签，按惯例可豁免（其他多语 UI 通常也用本地原文显示语言名） |

**实质违规数**：0–1（取决于 "中文" 是否计入）

### 2.2 局部文案模块（`*_copy.rs` 模式）

发现 **30+ 处** Chinese 字符串字面量分布在组件目录的 `*_copy.rs` 文件中：

- `components/sidebar/extensions_copy.rs`
- `components/sidebar/source_control/error_notice_copy.rs`
- `components/sidebar/source_control/history_compare_banner_copy.rs`
- `components/sidebar/source_control/change_item_counterpart.rs`
- 等等

**性质**：这些文件本身就是 i18n 实现，只是采用了"就近放置"模式（colocate with component），而非集中在 `apps/web/src/i18n/` 目录下。

**判定**：
- 它们都使用 `Locale::Zh => ...` / `Locale::En => ...` 标准 facade
- 它们都对称（每个 Zh 都有 En）
- ⚠️ **架构问题，不是 bug**：出现了**两套 i18n 组织风格**——集中式 (`i18n/*.rs`) + 就近式 (`*_copy.rs`)。Plan §11 没明确禁止任一种，但缺乏统一规范可能导致后续维护混乱。

### 2.3 Doc 注释中的中文（非违规）

`components/dashboard/actions_card.rs:4` 等多处文件顶部 doc comment 含中文（如 `//! 提供 "New Doc" 和 "Sync Now" 按钮。`），不影响运行时，符合宪章"代码注释与现有代码库语言保持一致"。
